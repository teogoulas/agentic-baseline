## Key Files — Content Requirements

### `core/skills/escalation-rules.md`
The most critical file. Define when agents MUST stop and ask vs proceed autonomously:

**Must escalate:**
- Any destructive action (delete, drop, truncate, rm -rf)
- Modifying auth, permissions, or security configuration
- Pushing to main/production branches
- Any action outside the defined project scope
- Security findings with CVSS ≥ 7.0
- When confidence is below ~70% on an irreversible action
- When a required tool or MCP is not installed — surface via tool-broker, never auto-install

**Can proceed autonomously:**
- Reading files, exploring codebase
- Writing new files, creating branches
- Running tests
- Installing dependencies
- Documenting findings

### `core/context/personal.md`
Scaffold with structure and TODOs. User will fill in:
- Preferred stack (languages, frameworks, DBs)
- Code style preferences
- Communication style
- Project patterns they use repeatedly
- Tools and versions in their environment

### `core/context/permissions-default.md`
Default permission boundaries that apply to all agents unless overridden by a project-level config file.

### `core/context/tool-registry.md`
A living catalog of what tools and MCPs are currently installed, what capabilities each provides, and when they were last verified. Updated by the tool-broker. Not edited manually.

Seed structure:
```
## Installed Agent Tools
- Claude Code — code editing, file ops, git, MCP host
- OpenClaw — local automation, email, scheduling, web search

## Active MCPs
- Google Calendar — [capability summary]
- ClickUp — [capability summary]
- Google Drive — [capability summary]
- Slack — [capability summary]
- Gmail — [capability summary]

## Last Verified: YYYY-MM-DD
```

### `core/agents/orchestrator.md`
The meta-agent. Should:
- Decompose large tasks into parallel subtasks
- Route each subtask to the right specialist agent
- Aggregate results into a structured summary
- Consult `tool-registry.md` before assuming a capability is available
- Delegate to tool-broker when a needed capability is missing

### `core/agents/tool-broker.md`
Manages the tool and MCP lifecycle. Three modes:

**Discover (per task):** Given a task, identify what capabilities are needed and whether they exist in `tool-registry.md`. If a capability is missing, surface the best option and ask the user before proceeding. Never auto-install.

**Audit (monthly):** Review installed MCPs and tools against actual usage patterns — flag unused, broken, or superseded ones. Scan the MCP ecosystem for new servers relevant to the user's workflow. Output a proposal for user approval.

**Update (after approval):** Apply approved changes to `tool-registry.md` and relevant adapter configs.

The tool-broker never installs or removes anything autonomously.

### `core/agents/security-auditor.md`
Specialist agent for security review tasks. Should:
- Know how to read code for common vulnerability classes (injection, auth bypass, insecure defaults, etc.)
- Apply `core/skills/security-audit.md` and `core/skills/findings-format.md`
- Always output findings in the standard findings format
- Escalate any CVSS ≥ 7.0 finding immediately — do not continue auditing until acknowledged
- Never attempt to exploit — document and escalate only

### `feedback-loop/post-task-template.md`
A prompt the user pastes into their agent after completing a significant task. Should ask:
1. What did I have to explain more than once?
2. What output format needed fixing?
3. What escalated that should have been autonomous?
4. What ran autonomously that should have escalated?
5. What tool would have handled this better?
6. Was any required tool or MCP missing — what should be added?
7. Suggested skill additions/edits with content
8. Suggested context updates

Output: structured JSON for easy processing.

### `update-loop/research-prompt.md`
A prompt to run monthly with web search enabled. Scans for:
1. New models — update default model recommendations?
2. New agentic coding tools worth adding
3. New multi-agent architectural patterns
4. Security vulnerabilities in tools the user uses
5. Deprecated patterns to remove

Output format:
```json
{
  "scan_date": "YYYY-MM-DD",
  "findings": [
    {
      "category": "models|tools|architecture|security|deprecation",
      "action": "ADD|UPDATE|REMOVE|MONITOR",
      "title": "short title",
      "summary": "2-3 sentence summary",
      "impact_on_baseline": "which file(s) should change and how",
      "priority": "high|medium|low",
      "sources": ["url1", "url2"]
    }
  ],
  "proposed_diffs": [
    {
      "file": "core/skills/example.md",
      "change_type": "append|replace_section|new_file",
      "content": "the actual content to add or change"
    }
  ]
}
```

User reviews, approves, and agent applies as: `chore: monthly baseline update YYYY-MM-DD`

### `update-loop/mcp-review.md`
A prompt to run alongside the monthly update. Instructs the tool-broker to:
1. Check each entry in `tool-registry.md` — still functional? Still used?
2. Scan the MCP ecosystem for new servers relevant to the user's workflow
3. Flag MCPs to remove, update, or add with rationale
4. Output a proposal — no changes made until user approves

### `bootstrap.sh`
Should:
1. Detect which tools are installed (`claude`, `codex`, `gh`, `openclaw`, etc.)
2. Run only the relevant adapter `install.sh` scripts for detected tools
3. Print a summary of what was set up and what was skipped
4. Remind user to fill in `core/context/personal.md` TODOs if unfilled

Adapters are thin — they reference `/core` files rather than duplicating content.

### `adapters/claude-code/CLAUDE.md`
References core context and adds Claude Code-specific config:
- Model preferences
- MCP servers (sourced from `tool-registry.md`)
- Allowed tools
- Reference to core escalation rules

### `adapters/codex/AGENTS.md`
Same structure as CLAUDE.md but in Codex/AGENTS.md format. Codex supports SKILL.md in `~/.agents/skills/` — install.sh should symlink core skill files there.

### `adapters/openclaw/README.md`
Maps core skills and agent definitions to OpenClaw's task automation format. OpenClaw is best suited for: multi-step local automation, email and calendar orchestration, web research pipelines. The mapping should clarify which core skills apply to OpenClaw's execution model and which are coding-agent-specific.

## Principles

- **Tool-agnostic core:** `/core` files never mention specific tools by name
- **Discovery over assumption:** If a task needs a tool or MCP, the tool-broker surfaces it and asks — it never assumes availability
- **Placeholders over assumptions:** Unknown preferences use clear `[TODO: ...]` markers throughout
- **Composable:** Each skill file is independently useful and referenceable
- **Concise:** Skill files are dense and actionable — agents read these as instructions
- **Living system:** Everything is designed to be updated, not set-and-forget

## Job 1: Monthly Baseline Updater

### Purpose
Keep `/core` skills, agent definitions, and adapter configs current with the fast-moving AI field.
Run once a month, or whenever a major tool or model release happens.

### `update-loop/run-update.sh` — what it should do
1. Auto-generate `baseline-snapshot.md` by concatenating key files from `/core` with metadata
2. Print current date and last update date (from `update-log.md`)
3. Output the exact command to run the research agent with web search enabled
4. After user approval, agent applies proposed diffs as a git commit

**MCP Ecosystem**

> Note: Podcast episode discovery via web search is unreliable. For podcast coverage, manually add notable episodes to `improvement-log.md` or check sources directly.

### `intelligence/digest-prompt.md` — sections

**Section 1: Must-Know This Week** — 3-5 developments directly affecting your work as an agentic engineer. Each: title, 2-sentence summary, why it matters, link.

**Section 2: New Tools & Releases** — agentic coding, multi-agent frameworks, security tooling, developer infrastructure.

**Section 3: Interesting Papers** — 2-3 papers, plain-language summary, practical implication.

**Section 4: Content Pick** — one article worth reading this week and why.

**Section 5: On the Radar** — 2-3 early signals not yet mainstream.

Output: clean markdown, opinionated, scannable in under 5 minutes. Saved to `/intelligence/digests/YYYY-MM-DD.md`. No filler.

### `intelligence/run-digest.sh` — what it should do
1. Check date of last digest in `/intelligence/digests/`
2. Set scan window (7 days for weekly, 30 for monthly)
3. Output the exact Claude Code command to run with web search enabled
4. After agent runs, git commit the new digest file

### Delivery options (document in README)
- **Slack:** pipe digest to a personal channel via MCP
- **Gmail:** send to self via Gmail MCP
- **ClickUp:** create a task with digest as note via ClickUp MCP
- **Plain file:** read from `/intelligence/digests/`

## How to Start

```bash
mkdir agentic-baseline && cd agentic-baseline
git init
# Build the structure above, then:
./bootstrap.sh
```

Fill in `core/context/personal.md` TODOs before first use. That file is the highest-leverage input — everything else is generic until it is filled.

**Three loops to establish as habits:**
- **After every task:** run `feedback-loop/post-task-template.md`
- **Every week/month:** run `intelligence/run-digest.sh`
- **Every month or on major release:** run `update-loop/run-update.sh` (includes MCP review)
