# Git Workflow

Conventions for all git operations across projects.

---

## Branch Naming

```
[type]/[short-description]

Types:
  feat/     — new feature
  fix/      — bug fix
  chore/    — maintenance, tooling, deps
  docs/     — documentation only
  refactor/ — no behavior change
  security/ — security fix or hardening
  hotfix/   — urgent production fix
```

Examples:
- `feat/user-authentication`
- `fix/null-pointer-on-login`
- `chore/monthly-baseline-update-2026-05`

---

## Commit Messages

Format: `[type]: [imperative description]`

Rules:
- Imperative mood — "add", "fix", "remove" not "added", "fixed", "removed"
- Under 72 characters for the subject line
- Body (optional): explain *why*, not *what*
- Reference issue/ticket if applicable

Examples:
```
feat: add JWT refresh token rotation
fix: handle empty payload in webhook receiver
chore: tool-registry update 2026-05-04
security: remove hardcoded API key from config
```

---

## Workflow

1. Always branch from `main` (or the project's default branch)
2. One logical change per branch — keep PRs reviewable
3. Rebase on main before opening a PR (never merge main into your branch)
4. PR must pass CI before merge
5. Delete branch after merge

---

## What Requires Escalation

Per `core/skills/escalation-rules.md`:
- Pushing to `main`, `master`, `prod`, or equivalent — always escalate
- Force push to any branch — always escalate
- Amending a commit that has already been pushed — always escalate

---

## Commit Hygiene

- Commits should be atomic — one logical change, fully working
- Do not commit generated files, build artifacts, or secrets
- `.gitignore` should be set before the first commit on any project
- If a commit would break the build or tests, it should not exist

---

## Auto-Generated Files

Files auto-generated by scripts (e.g. `baseline-snapshot.md`, digests) should be:
- Listed in `.gitignore` if ephemeral, OR
- Committed with `chore:` prefix and a clear automated commit message
- Never manually edited after generation
